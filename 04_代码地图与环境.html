代码地图与环境

去哪个目录

下列路径相对研究服务器工作区根目录，记为 $WORKSPACE。这些是服务器定位信息，资料包未复制完整实验仓库。

工作区有多个独立项目，根目录不是统一 Git 仓库。修改、测试和提交应在实际所属项目中进行。旧 README 的“最新结果”可能已经被后续审计或新实验覆盖。

推荐的代码阅读顺序

心脏方向先看数据与推理约定，再追 infer_cine.py → core.py → 官方模型/高斯渲染，最后读 run_study.py 的对照与选模逻辑。推理输入是 observed；target 只用于训练损失或评测。

FM 方向先看 codec.py → condition.py → source.py → vector_field.py → ode.py → model.py。Scope A 保留原条件分支，Scope B 用替代分支。Euler N 步通常 NFE=N；这里的 Heun N 步为 NFE=2N。需要一起报告端到端耗时。

当前运行环境参考

MRI 现有 stadnet 环境记录为 Python 3.11.16、PyTorch 2.11.0+cu128；Blackwell 上扩展编译工具链记录为 CUDA 13.2。包内 环境参考 是已有实验记录，不能据环境名猜测包版本。

上游 STADNet 的历史要求是 Python 3.6 / PyTorch 1.4，与当前环境不同；照其旧 README 全局降级会破坏现有工作。新环境应单独创建，先完成 CPU 检查，再验证 CUDA 扩展兼容性。

资料包内立刻可跑：只用标准库和 CPU

解压后，在资料包目录执行：

python3 tools/read_snapshot.py
python3 tools/check_package.py

第一个脚本读取包内冻结快照，第二个校验所有文件哈希和本地链接。它们不连接研究服务器，也不启动模型训练。若系统的 Python 3 命令名为 python，将命令中的 python3 替换为 python。

进入服务器后的最小上手任务

确认已配置评价项目所需的 cardiac-mra 环境和依赖后，可以运行合成数据冒烟：

cd "$WORKSPACE/心脏重建评价模型"
conda activate cardiac-mra
CUDA_VISIBLE_DEVICES="" python -m src.cli.smoke --config configs/ranker_mvp.yaml --synthetic

这是工程检查，不能作为医学效果实验。输出路径与依赖说明以项目 README 为准；如要安装依赖，在自己的隔离环境内执行。

涉及代码变更时，按项目要求运行相关测试。评价 MVP 为 python -m pytest -q；FM-STADNet 为既定环境下的 python -m pytest tests/ -q。本资料整理没有重新运行这些模型测试；历史报告中的通过数是对应实验当时的记录。

它们会更新；本包不会自动同步。当前训练占用物理 0、3 号 GPU。新人先读状态和报告，另建实验输出目录，再与负责人协调 GPU 时段；继续训练/重启应沿用现有控制器与恢复机制，避免重复启动同一任务。

参考配置怎么用

包内 Stage 1 和 Stage 2 保留本次参数，只将机器路径替换成 <RUN_DIR>。它们用于阅读训练协议，不能脱离源码、数据和启动器直接运行。YAML 中 num_gpu: 1 沿用上游单进程设置；实际双卡由外部模型并行启动器实现。
