# MRI 科研工作台

建立日期：2026-10-27。用途：支持文献检索、基线选型、方案设计、实验记录、结果分析和汇报。

这是按需运行的研究工作流。Skill 提供步骤和证据规则；搜索工具提供在线资料；训练依赖实际代码、数据与服务器。它不会自行常驻运行或产生实验结果。

## 从这里开始

1. 阅读 `项目状态.md`，更新最新实验状态；10 月 17 日的旧快照不能视为今天的状态。
2. 调用 `$mri-research-workflow`，说明本轮任务。第一次建议做基线文献初筛。
3. 每轮结果保存到本目录，沿用已有文献 ID、实验 ID 和决策记录。
4. 在研究服务器执行模型训练；在本机阅读、整理小型表格和报告。

## 可以直接发送的指令

### 查找文献与候选基线

> 使用 $mri-research-workflow，读取科研工作台/项目状态.md。围绕 LR-only 心脏 MRI 任意倍率超分做一轮探索性检索，兼顾确定性超分、Gaussian 表示、条件 FM 和一步生成。首轮最多详细整理 12 篇；逐篇核实论文和官方代码，记录输入、退化、倍率、训练成本、证据位置和限制，选出最多 3 个值得做小规模验证的候选。不要把未查到的信息补成事实。

### 设计实验

> 使用 $mri-research-workflow，基于已有文献和候选表，提出 2–3 个可证伪的假设，选一个成本最低、能排除关键疑问的实验。写出对照、数据划分、唯一主要变量、预算、主指标、通过标准、停止条件和负责人；把没有确定的条件列出来。先输出方案，不启动训练。

### 分析结果

> 使用 $mri-research-workflow，分析我提供的日志和结果。先核对数据、初始化、预算、倍率和测试集使用历史，再比较患者等权指标、时序误差、耗时和失败案例。说明结果支持什么、不支持什么，以及下一步应继续还是停止。

### 生成周报

> 使用 $mri-research-workflow，读取项目状态、实验卡和决策记录，生成本周完成事项、证据、失败实验、阻塞问题、下周三项优先工作，以及需要另一位负责人提供的信息。所有状态附日期。

## 完整流程与交付

| 环节 | 自动协助内容 | 可检查交付 | 进入下一环节的条件 |
|---|---|---|---|
| 任务定义 | 整理已知条件和待确认项 | 项目状态 | 输入、任务、主要目标明确 |
| 文献检索 | 扩展检索词、查找原文、去重 | 检索日志和文献卡 | 关键事实有来源，未获取全文明确标注 |
| 基线选择 | 对齐任务条件，核查代码 | 候选对比和选择理由 | 区分开发基线、对比方法和输入不匹配方法 |
| 实验设计 | 形成假设、对照和决策规则 | 实验卡 | 数据、资源、指标和预算可落实 |
| 工程验证 | 检查输入输出、梯度、小样本学习 | 运行记录 | 能运行且没有已知协议错误 |
| 正式实验 | 在已有授权与预算内执行或整理命令 | 配置、版本、日志和检查点索引 | 运行可恢复、结果可追溯 |
| 结果分析 | 汇总指标、检查不确定性和失败案例 | 结果报告 | 对照可比，结论与证据一致 |
| 写作汇报 | 草拟图表、方法、结果、局限与周报 | 稿件和证据对应表 | 每项主张能追溯到文献或实际实验 |

只有明确提出定期检查后，才另设时间表；当前未创建定时任务。无人值守的训练还需服务器连接、执行权限、资源预算和停止条件。

## 两人分工建议

- 你：任务表、文献与候选筛选、实验卡、结果分析和周报。
- 另一位负责人：服务器状态、数据与代码版本、已有权重、运行环境、训练执行和异常恢复。
- 共同决定：输入协议、开发基线、主指标、计算预算和最终研究主张。以上为建议，实际分工以你们约定为准。

## 技能组合

- 已有：PDF 阅读、表格分析、Word 文档、PPT 汇报、可视化。按任务加载，不重复安装。
- 本次定制：`mri-research-workflow`，负责把项目阶段和证据串起来。
- 可选第三方：K-Dense 的 literature-review、scientific-brainstorming、scientific-critical-thinking。此次仅核查入口，没有安装或执行其脚本；部分可选功能需要额外服务、密钥或文档工具链。
- 可选官方目录技能：jupyter-notebook；只有需要 notebook 交付时再安装。

技能本身不保证检索穷尽、创新性成立或实验成功。首次文献工作定位为探索性检索；如要投稿系统综述，需要另立完整检索与筛选协议。
